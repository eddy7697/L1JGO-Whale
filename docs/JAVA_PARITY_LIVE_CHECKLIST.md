### V-10：血盟戰同意與自動休戰（1-5、1-6，中風險）

1. 在測試伺服器將 `[gameplay] sim_war_time` 設為 `"2m"`，重啟後才建立戰爭；正式預設是 `"240m"`。準備兩個無城堡血盟 A、B，兩位盟主皆為 16 級以上王族且在線，另備一位不屬於雙方的觀察者。
2. A 向 B 宣戰，B 先拒絕；A 再宣戰，B 同意。確認同意之前沒有戰爭，拒絕時 A 收 236，同意後雙方盟員收到開戰訊息；觀察者不收模擬戰專屬封包。
3. 分別在新建的戰爭測試投降（221）與休戰（222）：先拒絕再重新請求並同意。拒絕不結束戰爭，同意才結束，雙方收到各自的結束訊息。
4. 再開一場戰爭，不送任何結束請求，等待超過兩分鐘後第一個 tick。雙方自動休戰，log 有「血盟戰時間到，自動休戰」，不重複廣播。
5. 等待同意期間讓提出方退盟／換盟／重登，或讓任一方失去盟主資格，再回覆舊對話；不得替別的血盟開戰或結束其他戰爭。新的正常請求仍應可操作。
6. 用 15 級王族及對方盟主離線的情況測試宣戰，分別收到 232、218；再按既有 V-1～V-3 驗證攻城仍能直接宣戰及正常結束。

失敗時備案：先確認 `S_Message_YN` opcode 219 的訊息號為 217/221/222，並記錄 `C_Attr` 回應模式與序號。若客戶端不顯示對話，再依 Java 與既有交易對話的序號機制調整；若按鈕無作用，確認專用請求狀態、雙方連線／血盟／盟主資格及原戰爭仍有效，不可為了讓舊回覆生效而省略檢查。

結果：未實機驗證。240 分鐘時鐘邊界已由自動化測試確認，不需實機等四小時。

### V-11：寵物指定攻擊目標（1-7，高風險）

1. 在一般戰鬥區召喚自己的寵物，設為攻擊態勢，再按「指定攻擊目標」。確認選目標游標正常顯示且不斷線，依序指定怪物、其他玩家、其他玩家寵物及召喚物。
2. 用警戒態勢重測；防禦、休息、散開、召回態勢不能藉指定目標強制開啟攻擊。取消選取、點空地或已消失物件不得改選其他目標。
3. 令玩家或其寵物目標進入安全區，再看追擊是否停止；隔牆、不同地圖或副本實例不能隔空造成傷害。不能指揮別人的寵物，也不能攻擊自己或自己的夥伴。
4. 以具有無敵／反射效果的目標測試，再用低血量目標確認死亡、主人 PK／決鬥歸屬正常。此項請使用可重置的測試角色。
5. 寵物比賽開始後，嘗試指定別的場外目標；原比賽目標與結算應維持正常。

失敗時備案：先抓包確認伺服器送 Java 的 opcode 54 + D(寵物 ID) + 三個 C(0)，客戶端回 opcode 223 + D(寵物 ID) + C + D(目標 ID)。若這版客戶端不接受 54，依抓包結果測試原 Go 的 opcode 236／末位 C(2)，每次只改一種格式並記錄客戶端版本；不要同時送兩套封包。若能選但不攻擊，檢查寵物模式、目標有效性與 AI 接線。

結果：未實機驗證。本項接通指定目標與既有戰鬥流程；寵物完整戰鬥數值、食物系統及全域 `NonPvP` 設定缺口仍屬原盤點其他工作。可指定的 NPC 限 `L1Monster`，不包含商人、守衛、塔、門、木人、娃娃或隨從；召喚物受擊與死亡已接上，召喚物反擊寵物的 AI 尚未新增。這些限制不以客戶端實測通過視為已實作。
