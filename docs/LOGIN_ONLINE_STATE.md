# 登入與在線狀態（Java 對照）

核對日期：2026-10-14。來源為 `E:/L1JTW-Eddy/src/l1j/server/server`，實作分支 `codex/login-online-state`。

## Java 的實際行為

- `C_AuthLogin.java:91-119` 每次讀取帳號並驗證密碼；資料庫 `online=1` 時回登入結果 7，**保留舊連線**。先前盤點將所有重複登入描述為「踢舊」並不正確。
- `LoginController.java:63-78` 只有在資料庫為離線、記憶體仍有該帳號時，才走舊連線通知 357、約一秒後斷線，以及拒絕新連線的例外路徑。這不是直接用新連線接管角色。
- `LoginController.java:70` 的人數限制包含選角中的帳號；`Account.isGameMaster()` 在登入限制中定義為 `access_level > 0`，包含監察員。`MaximumOnlineUsers` 預設 30。
- `GameServer.java:191,250` 在接受連線前重設角色與帳號的在線旗標。斷線在 `ClientThread.run()` 的 finally 中清理角色、帳號與登入索引；回選角保留帳號在線。
- Java 有吞掉資料庫錯誤、未綁定帳號時 `kick()` 空參照等缺陷；本次不複製這些錯誤。

## Go 實作

| 情境 | 行為 |
|---|---|
| 啟動 | 綁定監聽埠後、啟動 AcceptLoop 前，取得資料庫／schema 的專用連線 advisory lock，再以交易清除 `accounts.online`、`characters.online_status` 殘留；失敗即中止啟動。第二個核心不能重設第一個核心的在線狀態。 |
| 登入 | 密碼、封鎖檢查通過後，以條件 UPDATE 原子標記在線，再綁定帳號與 Session，最後回成功及角色列表。資料庫失敗不回登入成功。 |
| 一般重複登入 | `online=true` 回登入結果 7；不踢舊、不移轉持有者。錯誤密碼不影響在線帳號。 |
| 例外碰撞 | DB 離線但仍有活躍持有者時，舊角色收到 357，停止接受操作並約一秒後關閉；新連線拒絕。舊連線已關閉或等待離線重試時，只回 7 等待清理。 |
| 逾時但可能已寫入 | 即使 UPDATE 的結果未知，也保留該帳號的清理責任，在後續輸入輪詢重試清除；不讓帳號只能等重啟解鎖。清理以原帳號為鍵，避免同一連線改試其他帳號時誤清新帳號。 |
| 選角／回選角 | 保留帳號持有者與在線名額。進世界前額外防止同一 Session 或角色重複加入世界索引。角色在線身分仍使用現有世界索引，未新增另一組 DB 執行期狀態來源。 |
| 斷線 | 既有角色／背包清理流程執行後，只有目前持有者可以清除帳號旗標。舊連線重複或延遲清理不會影響新登入。 |
| 離線寫入失敗 | 保留持有者，每次操作最多等待 2 秒、重試間隔至少 1 秒，恢復後解除。持續 DB 故障期間不開放同帳號重入，日誌記錄錯誤；沒有丟棄未完成清理的固定重試次數。 |
| 正常關機 | 除既有角色存檔外，關閉並清理所有 Session，包含選角畫面中的帳號；結束前再試一次離線寫入，失敗回報錯誤，重啟清理仍可復原。 |
| 資料庫鎖連線中斷 | 背景每 5 秒檢查專用連線，失敗通知主迴圈停止核心並關閉 Session，不再用舊快照覆寫可能由另一核心接手的資料；檢查不阻塞輸入處理。此服務仍是單核心／單 schema 部署，不是多核心無縫接管方案。 |

登入帳號名稱依 Java 限制為 1–32 個英數、底線、句點、`@`、`-`，密碼最多 32 個字元；缺少結尾 NUL 的登入欄位不會建立帳號。已認證的連線不能藉重送登入封包切換帳號。BeanFun 的登出動作現在也可在登入後進入既有斷線清理流程。

設定位於 `[server] max_online_users = 30`，`0` 表示僅允許 `access_level > 0` 的帳號，負值會拒絕啟動。舊設定檔未填此鍵時採 30。

本機 Java 的 `config/server.properties` 為 `AutomaticKick = 0`。本次未啟用 Go 原先尚未接線的 `network.read_timeout`，避免額外引入 60 秒無封包即踢人的差異；斷線清理在 TCP 關閉或網路錯誤被偵測後進行。
